### Transition and reading budget

The current stage retains its previous layer for 650 ms. CSS also gives a text/media handoff a 200 ms outgoing fade, with 600 ms fade/slide or 650 ms zoom entrances delayed by 200 ms. A four-second zoom card therefore has only about 3.15 seconds fully settled even with immediate state delivery; “four seconds” alone is not a readability guarantee.

Freeze every decisive native scene as `transition: cut`; freeze short native information cards as `cut` as shown below. This uses existing behavior and leaves the global 650 ms machinery unchanged. `cut` removes the entrance animation (the existing text-handoff bookkeeping/delay remains); budget conservatively 3.8 seconds minus network/render delay before the recap release. Do not rely on the previous clue staying visible while the recap downloads. On an unimpaired device require decisive text fully readable by 30,500 and at least 3,000 ms of unobstructed reading before 34,000; measure every phone/projector capture. Full comprehension/typing still needs review, especially long Q2/Q6 answers: the server allows ten seconds from decisive release to closure, but the card itself has four seconds.

Do not reduce font size below the existing floor or weaken the credit-safe region to force a pass. Pending native text must not overlap outgoing text. Recap imagery must remain nonessential so teams can type while it plays.
