## 3. Attribution architecture

```
media/q1..q6/manifest.json ─┐  scripts/media/attribution.mjs   server/content/attribution.json (server-only)
media/sources.json ─────────┴─► (scene → clip → shots → sources) ─► attributionFor('qN') → ServerQuestion.attribution
                                                                                 │
GameEngine.reveal(round)  ── throws while the round is open ──► RoundReveal.attribution (this question only)
        │
views.ts (unchanged): adminView / teamView / screenView put `reveal` in a view only when
`round.closed_at !== null`, per socket, per room → AttributionPanel renders it on demand
```

- **No new channel.** The credits ride on the existing reveal, so they inherit session authentication, room
  scoping, role projection, closed-round gating, refresh/reconnect/restart behaviour and the clearing on
  advance (the next question's round has no reveal until it closes).
- **Only this question:** entries come from the question's own manifest; a unit test fails if any question's
  credits contain the answer of a later question (Q4's room photo is titled with Q1's answer — Q1 is always
  revealed first).
- **Never in the client:** the JSON is read with `fs` on the server; `check-bundle` scans `dist/` for every
  source page URL, Commons title, creator and licence-evidence string.
- **Licences:** a fixed code table (CC BY 2.0/4.0, CC BY-SA 2.0/3.0/4.0, OFL 1.1, PD variants) gives names and
  URLs; nothing is inferred from text. Jurisdiction-limited public domain is `pd-qualified` and labelled
  "Phạm vi công cộng có điều kiện" with its note — never plain "public domain".
- **Modifications** are derived from each shot's actual parameters (crop/zoom, pan, fade, captions, blurred
  backdrop, thumbnail use, map redraw, encoding).
- **Share-alike:** a clip containing BY-SA material is listed with the highest BY-SA version among its
  sources; this matches every clip licence recorded at production time (c05, c07, c10, c13–c16, c18, c21,
  c27, c29).
- Own illustrations/graphics are one "Tác phẩm gốc của nhóm thực hiện" entry (no licence claimed).

## 7. Transition (Q4 ≈ 11 s, video b2 → text b3)

**Reproduced** (`e2e/transition-probe.mjs`, per-frame sampling): the outgoing video layer stayed at opacity
1.00 for ~650 ms under the sliding-in text card, whose layer is transparent → "14/9/1985 · 10 đồng cũ = 1
đồng mới" and its credit visible through the new text in **38 frames** (11.02–11.65 s).

**Cause:** scene layers had no background and the exit layer had no exit animation.

**Fix:** visible layers carry the stage background (a finished scene always covers the previous one); a change
involving a text scene fades the old layer out in 0.2 s and starts the new scene's own transition 0.2 s later;
video→video keeps the true cross-fade. No new clock or timer (CSS only; the existing 650 ms clean-up is
unchanged); reduced motion: the existing global rule makes the change instant.

**After:** 0 overlapping frames on the laptop and projector (141–148 frames sampled), one frame of plain stage
background between scenes (no black, no duplicate content). Before/after: [q4-transition-before-after.jpg](media-review/m33/q4-transition-before-after.jpg).
All six resilience runs still pass their scene-order, catch-up and drift checks (§9).

## 11. Known limitations

- The credits panel is local to each device: the projector operator opens it on the projector screen (the
  admin cannot open it remotely).
- `FitBox` floor scale is 0.55: Q3 e7 on a 360 px phone uses it (32 px value, 16 px text); denser future
  statistics might reach the floor and then rely on the wrap fallback.
- The laptop player stage is 645 px wide at 1366×768 (existing layout; not changed).
- Reduced motion relies on the existing global CSS rule; exercised in E2E for the Q4 transition only.
- In-round credits stay abbreviated by design; the complete attribution appears only after the reveal.
- Safari/iOS, Firefox and real classroom Wi-Fi not tested; no classroom rehearsal yet; no deployment work.
