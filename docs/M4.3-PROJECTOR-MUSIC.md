# M4.3 — Projector background music

The projector has one **Bật nhạc / Tắt nhạc** toggle. Default is OFF on every page load. The separate video-audio control was removed from the projector; all production scene MP4s remain muted and unchanged. Players and admins have no music control or music player.

## Supply exactly four files

Create `server/media/music/` on the game server, then place the supplied, authorized MP3s there:

```text
server/media/music/lobby.mp3
server/media/music/intro.mp3      (M4.3 step 2: one short effect for the 5 s question intro)
server/media/music/question.mp3
server/media/music/result.mp3     (M4.3 step 3: one short effect when a question's results appear)
```

All four are optional. Names must be lowercase `.mp3` exactly as above (Linux servers are case-sensitive). The supplied files are versioned in Git at these four paths only (`.gitignore` excludes anything else in the directory); they live outside `public/` and `dist/` and are never bundled into the client. Do not add them to scene manifests or the scene registry. `AppOptions.musicRoot` is an isolated-test override, not a public route or a new environment setting. Missing files do not prevent startup. Once the files are copied with server read permission, no client rebuild is needed; turn music OFF/ON to retry the current permitted track. The projector reports an unavailable track and gameplay continues; OFF/ON retries in the current phase.

Use a decodable MP3 with a finite duration. The intro effect is one generic sound used for every question; ideally ≤ 5 s. It plays once from the intro start; a longer file is cut at the server's active start, a shorter one leaves silence for the rest of the intro. It never extends the intro. The question track should contain at least 40 seconds of useful audio, beginning at the intended round start; the server deadline truncates longer tracks. A shorter track ends in silence and is not looped or restarted. Lobby music loops. Check actual licensing, loudness, abrupt loop seam, any spoken answer disclosure, and audible starts/ends when the supplied files arrive. Fixture tones used in tests are not deliverable music.

## Playback policy

| Room phase | Enabled behavior |
| --- | --- |
| `lobby` | Lobby track starts at zero, loops. The generic intro effect is preloaded once (see below). |
| `intro` | Lobby stops; intro effect plays once, aligned to `serverNow - introStartedAt`, stopped at the active start. |
| `active` | (Result effect preloaded, never played.) Question track, same definition for Q1–Q6, aligned to `serverNow - startedAt`. |
| `revealed` | On a live `active → revealed` transition of the round: question audio stopped, result effect once (not looped), then silence. Never on mount/refresh/reconnect into a result, duplicate states, or OFF/ON. |
| `ready` | Silence; lobby never resumes between questions. The generic intro effect may be preloaded (no playback). |
| `finished` | Lobby track starts at zero again, loops. |

OFF pauses immediately, aborts loading and releases the source/Blob URL. ON follows the current phase. The only prefetches are the two generic effects, each fetched at most once per phase while music is ON and never played from the prefetch. The intro effect is fetched in lobby/ready. The result effect is fetched during the active round, after its first visual (so it never competes with the opening video), so it can sound as soon as the server closes the round. They carry no question data. A preload still pending when its phase ends is aborted (playback then fetches on its own, one request, no gameplay delay); a failed preload is not retried in the same phase; OFF drops cached effects so ON re-reads the server files; a decode error drops the cached effect. Lobby and question audio are never prefetched. Enabling during an active question seeks to the current round position, not zero. A round change gives a new playback identity; a submission-count update or any of the eight visual scene changes keeps the same player/source.

The question waits for SceneStage's first ready visual promotion. A delayed opening video therefore does not start question music behind the pre-question lobby/neutral stage. A visible native clue or video failure fallback also counts as the visual experience, allowing gameplay to proceed. After loading, position is still relative to the original server start; no soundtrack shift, pause compensation or deadline extension is introduced.

One persistent `<audio>` element belongs to ScreenRoom, separate from SceneStage. The controller uses the existing room phase, round ID, start/deadline and server-clock offset. It has an independent deadline timer and a 100ms alignment watchdog; ordinary room updates are not needed to stop audio at the deadline. Offset corrections re-arm the timer and correct drift greater than350ms. The browser/OS can suspend JavaScript or output devices; physical suspend/background behavior is still a manual acceptance check, not a hard real-time guarantee.

On disconnection it becomes silent. Reconnection waits for a fresh room view, fetches only the newly permitted track and aligns to current time. Refresh preserves pairing but resets music to OFF; the operator must click ON again. Rapid phase/toggle changes invalidate stale fetch/decode/play callbacks. There is no shared audio cache or six-player array. Blob URLs are revoked and loading/timers/event handlers are cleaned up on track change, OFF, re-pair or unmount.

## Security and browser policy

`GET /api/screen/rooms/:code/music/lobby` is allowed only in lobby/finished. `GET /api/screen/rooms/:code/music/intro` is allowed only in lobby/ready/intro (preload and playback of the generic effect), never during an active round, results or the final screen. `GET /api/screen/rooms/:code/music/question?roundId=<current-id>` is allowed only during that active round, strictly before its deadline. Both require an unexpired, unrevoked `screen` bearer session for exactly that room. Admin/team/other-room sessions are refused. Every request (including range/HEAD handling by Express) passes the same authorization; no unauthenticated static audio directory is mounted. `GET /api/screen/rooms/:code/music/result` is allowed only in active (preload) and revealed (playback); never lobby/intro/ready/finished. The fixed four-name allowlist plus realpath containment rejects traversal and escaping symlinks. Responses use private/no-store, audio/mpeg, nosniff and same-origin resource policy. Optional missing files return404 only after authorization.

An authorized file already delivered to a browser cannot be recalled; phase rules control new server delivery and the cooperative projector's playback. These soundtracks must contain no unreleased clues/answers.

The toggle records operator intent; **Đang phát nhạc** appears only on the audio `playing` event. Browser rejection is shown separately and never stops video or scoring. Desktop Chrome is tested without the autoplay bypass flag. Browsers may still reject async audible playback after a fetch; the UI asks the operator to turn music OFF/ON and browser sound permission may be needed. This follows [Chrome's autoplay guidance](https://developer.chrome.com/blog/autoplay/) and [WebKit's user-gesture policy](https://webkit.org/blog/6784/new-video-policies-for-ios/). Do not promise automatic audible restoration after refresh or cross-browser autoplay acceptance.

## Verification when real audio arrives

1. Verify the four exact server-side paths, licenses and decodability. Confirm question audio covers40 seconds, lobby loops cleanly and the intro effect fits the 5 s intro. No new video rendering is required.
2. Pair the projector, verify default OFF and zero audio requests, then click ON. Test loudness on the actual projector/speakers, including fullscreen; status must not obscure room, clues, timer or results.
3. Play all six rounds. Each start command stops lobby/silence, plays the intro effect once and cuts it at the active start; scene changes never restart question music. Each question aligns from its own start, each result plays the result effect once, ready is silent, final summary restarts lobby.
4. Enable late in a question and reload/reconnect. Confirm server-aligned position and original40s stop, with no lobby resumption between questions.
5. Check missing/corrupted files, browser sound denial, slow loading, OFF during load and rapid phase changes. Gameplay must continue. Test tab background/suspend on the actual Mac and browser.
6. Run `npm run typecheck`, `npm test`, `npm run build`, `npm run e2e:music`, `npm run e2e:projector`, and `npm run e2e:handoff` sequentially. Music E2E creates temporary valid MP3 fixture tones (including a 7 s intro effect that must be cut and a 2 s one that must end early) using the existing pinned FFmpeg and uses isolated SQLite; it does not read or overwrite supplied production music.
